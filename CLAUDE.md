# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

> `CLAUDE.md` and `AGENTS.md` are autogenerated by `/Init` (`forge-init.sh`). Do not edit directly — run `/Update` (`forge-update.sh`) to regenerate.

## What This Is

forge-avatar is a **content module** (markdown + shell hooks, no Rust) for the forge ecosystem. It loads a user's digital avatar — identity, preferences, goals, and self-knowledge — into AI sessions at startup. Think "dotfiles for AI identity."

**Layer**: Identity (first of forge-core's three layers: Identity / Behaviour / Knowledge). Loaded once at session start via `SessionStart` hook.

## Testing & Linting

```bash
bash tests/test.sh                        # all tests (structure, hook output, naming)
shellcheck hooks/*.sh tests/*.sh          # lint shell scripts
```

Tests use `assert_eq`/`assert_contains`/`assert_not_contains` with temp directory isolation. No external test framework.

Pre-commit hook runs shellcheck on staged `.sh` files automatically:
```bash
git config core.hooksPath .githooks       # enable pre-commit hook
```

## Shell Conventions

All scripts start with `set -euo pipefail`. Aliases for `cd`, `cp`, `mv`, `rm` are intercepted on this system:

- Use `builtin cd` (not `cd`)
- Use `command cp`, `command mv`, `command rm` (not bare)

## Architecture

### Hook dispatch

`hooks/hooks.json` registers a single `SessionStart` event that runs `hooks/session-start.sh`. When installed via forge-core, the dispatch binary calls this; when installed as a Claude Code plugin, `hooks.json` is read directly via `.claude-plugin/plugin.json`.

### session-start.sh flow

1. Resolve avatar root: `$FORGE_USER_ROOT/Resources/Avatar/` (fallback: `$HOME/Data/Vaults/Personal/Resources/Avatar/`)
2. Also checks orchestration dir: `$FORGE_USER_ROOT/Orchestration/` — exits silently if missing
3. Load `strip_front` function (from `$FORGE_LIB/strip-front.sh` if available, otherwise inline awk)
4. Emit **root files**: `Identity.md`, `Preferences.md` — strips YAML frontmatter and `# Heading`, outputs `## Section` + body
5. Emit **self-knowledge directories** in fixed order: Goals, Faultlines, Beliefs, Strategies, Models, Narratives, Challenges, Frames — each as `## Category`, with one file per item. Skips folder notes (files named same as directory)

### Content lives outside this module

The module provides the loading framework. Actual avatar content lives in the user's workspace at `Resources/Avatar/`. The `scaffold/` directory provides starter templates for new users.

### Dual installation modes

| Mode | Config | Hook discovery |
|------|--------|----------------|
| **forge-core submodule** | `module.yaml` | Dispatch binary reads `defaults.yaml` → runs `hooks/session-start.sh` |
| **Claude Code plugin** | `.claude-plugin/plugin.json` | Claude Code reads `hooks/hooks.json` directly |

Version must stay in sync between `module.yaml` and `.claude-plugin/plugin.json` (tested).

### Key env vars

| Variable | Set by | Purpose |
|----------|--------|---------|
| `FORGE_USER_ROOT` | forge-core dispatch | User content root — avatar reads `$FORGE_USER_ROOT/Resources/Avatar/` |
| `FORGE_LIB` | forge-core dispatch | Shared lib path (provides `strip-front.sh`) |
| `AVATAR_ROOT` | Test override | Direct path to avatar directory (bypasses standard resolution) |

## Skill: `/Avatar`

Defined in `skills/Avatar/SKILL.md`. Guided interview workflows for avatar creation and refinement:

- **Interview** — walk through all 9 sections with probing questions, write individual files
- **Refine** — challenge existing items (precision, consistency, currency, completeness, connections)
- **Export** — produce portable single-document avatar for other AIs
- **Import** — reconcile external AI interview results back into avatar files

Each avatar item is a separate file. Filename = descriptive title. Item ID (B1, FL3, etc.) lives in `aliases:` frontmatter, stable across sessions (append-only, never renumber).

## Scaffold Structure

`scaffold/` contains starter templates that users copy to their workspace:

- Core: `Identity.md`, `Preferences.md`, `Goals.md`
- Supporting: `Orchestration.md`, `Backlog.md`
- Directories: `Agents/`, `Patterns/`, `Templates/`
- Templates: `Agent.md`, `Pattern.md`, `Imperative.md`, `Insight.md`, `Idea.md`
